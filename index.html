CH-02OU Structure & User Management

A government-style Organizational Unit hierarchy was created mirroring real agency network design. Access is always assigned to groups, never individual users.

Create OU Hierarchy
New-ADOrganizationalUnit -Name "GOV-LAB" -Path "DC=local,DC=lab"
New-ADOrganizationalUnit -Name "Users" -Path "OU=GOV-LAB,DC=local,DC=lab"
New-ADOrganizationalUnit -Name "Computers" -Path "OU=GOV-LAB,DC=local,DC=lab"
New-ADOrganizationalUnit -Name "Admins" -Path "OU=GOV-LAB,DC=local,DC=lab"
New-ADOrganizationalUnit -Name "Service-Accounts" -Path "OU=GOV-LAB,DC=local,DC=lab"
Create Domain User Account
New-ADUser -Name "John Smith" -SamAccountName "jsmith" `
  -UserPrincipalName "jsmith@local.lab" `
  -Path "OU=Users,OU=GOV-LAB,DC=local,DC=lab" `
  -AccountPassword (ConvertTo-SecureString "P@ssword123!" -AsPlainText -Force) `
  -Enabled $true
Fix IPv6 DNS Hijacking (Troubleshooting)
reg add "HKLM\SYSTEM\CurrentControlSet\Services\Tcpip6\Parameters" /v DisabledComponents /t REG_DWORD /d 0xFF /f
!
Lesson Learned: UTM's virtual router was advertising its IPv6 address as DNS server via DHCPv6, overriding the IPv4 DNS setting. Always check nslookup to see the actual DNS server being used — not just what you configured. Disabling IPv6 at the registry level was required to force IPv4 DNS queries to DC01.
CH-03Password Policy & GPO Security Controls

The GOV-Security-Baseline GPO implements controls required by NIST 800-53 and DISA STIGs on all government systems.

NIST/STIG Compliant Password Policy
Set-ADDefaultDomainPasswordPolicy -Identity "local.lab" `
  -MinPasswordLength 12 `
  -PasswordHistoryCount 24 `
  -MaxPasswordAge "90.00:00:00" `
  -MinPasswordAge "1.00:00:00" `
  -LockoutThreshold 5 `
  -LockoutDuration "00:30:00" `
  -LockoutObservationWindow "00:30:00" `
  -ComplexityEnabled $true

Set-GPRegistryValue -Name "GOV-Security-Baseline" `
  -Key "HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System" `
  -ValueName "LegalNoticeCaption" -Type String -Value "AUTHORIZED USE ONLY"

Set-GPRegistryValue -Name "GOV-Security-Baseline" `
  -Key "HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System" `
  -ValueName "LegalNoticeText" -Type String `
  -Value "This system is for authorized users only. All activity is monitored and logged. Unauthorized access is prohibited and subject to criminal prosecution."
i
Legal Basis: The warning banner is required under DoD policy and 18 U.S.C. 2511 (Federal Wiretap Act). It establishes implied consent for monitoring and removes any expectation of privacy. Without it, reviewing user activity logs may be legally challenged. Every government computer in the US displays this banner.
CH-04NTFS Permissions & Access Control

NTFS permissions enforce role-based access control on shared folders. All access is granted to security groups — never individual users.

Create SMB Shares
New-SmbShare -Name "GOV-General" -Path "C:\Shares\GOV-General" -FullAccess "Everyone"
New-SmbShare -Name "GOV-Admin" -Path "C:\Shares\GOV-Admin" -FullAccess "Domain Admins"
Apply NTFS Permissions via PowerShell
# Grant GOV-Users Modify access to GOV-General
$acl = Get-Acl "C:\Shares\GOV-General"
$rule = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "LOCAL\GOV-Users","Modify","ContainerInherit,ObjectInherit","None","Allow")
$acl.SetAccessRule($rule)
Set-Acl "C:\Shares\GOV-General" $acl

CH-06PowerShell Automation Scripts

PowerShell automation reduces manual effort, ensures consistency, and creates auditable records of administrative actions. The bulk user import script created 5 accounts in seconds with perfect consistency.

Bulk User Import from CSV (One-liner Pipeline)
Import-Csv "C:\Scripts\new_users.csv" | ForEach-Object {
  $u = ($_.FirstName[0] + $_.LastName).ToLower()
  New-ADUser -Name "$($_.FirstName) $($_.LastName)" `
    -SamAccountName $u -UserPrincipalName "$u@local.lab" `
    -Path "OU=Users,OU=GOV-LAB,DC=local,DC=lab" `
    -AccountPassword (ConvertTo-SecureString "P@ssword123!" -AsPlainText -Force) `
    -Enabled $true -Department $_.Department -Title $_.Title
  Write-Host "Created: $u" -ForegroundColor Green
}
User Account Management Operations
# Disable account (offboarding)
Disable-ADAccount -Identity "edavis"

# Reset password (must meet complexity policy)
Set-ADAccountPassword -Identity "rjohnson" -NewPassword (ConvertTo-SecureString "G0v3rnm3nt@Lab2026!" -AsPlainText -Force) -Reset

# Force password change at next logon
Set-ADUser -Identity "rjohnson" -ChangePasswordAtLogon $true
AD Reporting — Export to CSV
Get-ADUser -Filter * -Properties Department,Title,Enabled | `
  Select-Object Name,SamAccountName,Department,Title,Enabled | `
  Export-Csv "C:\Scripts\AD_User_Report.csv" -NoTypeInformation
Register Scheduled Daily Report Task
Register-ScheduledTask -TaskName "Daily AD User Report" `
  -Action (New-ScheduledTaskAction -Execute "PowerShell.exe" -Argument "-File C:\Scripts\AD_User_Report.ps1") `
  -Trigger (New-ScheduledTaskTrigger -Daily -At "06:00AM") `
  -RunLevel Highest -Description "Exports AD user report daily at 6AM"

CH-07Security Event Analysis & Audit Policy

Windows Security event logs tell the complete story of system activity. Every login, failure, policy change, and account modification is recorded and queryable using PowerShell.

Query Failed Login Attempts
Get-EventLog -LogName Security | Where-Object {$_.EventID -eq 4625} | Select-Object TimeGenerated, Message | Format-Table -AutoSize -Wrap
Count Failed Logins by Account
Get-EventLog -LogName Security | Where-Object {$_.EventID -eq 4625} | Group-Object {$_.ReplacementStrings[5]} | Select-Object Name, Count | Sort-Object Count -Descending
Enable Critical Audit Policies
auditpol /set /subcategory:"File Share" /success:enable /failure:enable
auditpol /set /subcategory:"Removable Storage" /success:enable /failure:enable
auditpol /set /subcategory:"Process Creation" /success:enable
auditpol /set /subcategory:"Directory Service Changes" /success:enable /failure:enable
Daily Security Summary Script
$report = @"

Critical Security Event IDs

Every government sysadmin and SOC analyst must know these Event IDs. They are the language of Windows security monitoring.

4624
Successful Logon
Normal login. Multiple rapid 4624s at odd hours from unknown source = suspicious lateral movement.
4625
Failed Logon
Wrong password entered. Rapid failures in short period = brute force attack in progress.
4648
Explicit Credential Logon
User logged on using different credentials (runas). Could indicate lateral movement or pass-the-hash.
4672
Special Privileges Assigned
Admin-level logon. Unexpected 4672 from non-admin account = privilege escalation alert.
4720
User Account Created
New account created. Unauthorized creation during off-hours = possible backdoor account.
4725
User Account Disabled
Account disabled. Unauthorized disabling of admin accounts = active threat actor.
4740
Account Locked Out
Too many failed logins. Lockout storm across many accounts = credential stuffing or bad script.
4756
Member Added to Group
User added to security group. Unexpected addition to Domain Admins = critical immediate alert.
4768
Kerberos TGT Requested
Domain login initiated. Golden Ticket attacks appear as anomalous TGT requests.
4776
Credential Validation
NTLM authentication used. Pass-the-hash attacks use NTLM — monitor for unusual NTLM in Kerberos environment.
4634
Account Logoff
Session ended. Correlate with 4624 to determine session duration and user activity patterns.
4722
User Account Enabled
Disabled account re-enabled. Reactivating old disabled accounts = potential threat actor persistence.

STIG & NIST Controls Applied

STIG V-220726 // DISA
Removable Storage Denied
USB drives and all removable storage blocked via GPO. Prevents data exfiltration and malware introduction on classified networks.
STIG V-220700 // DISA
AutoRun Disabled
AutoPlay disabled for all drive types (value 255). Prevents automatic code execution from inserted media without user confirmation.
STIG V-220719 // DISA
Screen Lock — 15 Minutes
Screen saver timeout set to 900 seconds with password-protected lock. Prevents unauthorized access to unattended workstations.
DOD POLICY // Legal Banner
AUTHORIZED USE ONLY
Legal warning banner deployed via GPO. Establishes implied consent for monitoring under 18 U.S.C. 2511. Mandatory on all government systems.
NIST AU-3 // 800-53
Command Line Audit Logging
Process creation events include full command line arguments. Enables forensic reconstruction of attacker commands during incident response.
NIST AC-6 // 800-53
Least Privilege Enforced
NTFS permissions restrict file share access to authorized security groups. Standard users cannot access administrative shares.
NIST AU-2 // 800-53
Audit Policy — File Share
File Share auditing enabled for success and failure. All access to shared resources is now logged and auditable.
NIST AU-2 // 800-53
Removable Storage Auditing
Removable storage access events logged. Even if a USB is inserted, the attempt is recorded — supporting DLP investigations.
NIST IA-5 // 800-53
Password Complexity Policy
12-character minimum with complexity, 90-day max age, 24-password history. Meets NIST 800-63B and STIG requirements.

5 failed attempts triggers 30-minute lockout. Prevents automated password guessing and brute force attacks.

Troubleshooting Log

ISSUE: ARM64 vs x86_64 — Windows Server ISO incompatible with Apple Silicon Mac
The x64 ISO requires full CPU emulation on Apple Silicon causing severe performance degradation and installation failures with "License Terms not found" errors. Resolution: Used CrystalFetch app to download the ARM64-native Windows ISO directly from Microsoft servers. Reconfigured UTM VM to use Virtualize mode (ARM64 native) instead of Emulate mode (x86_64 emulation). Performance improved dramatically.
ISSUE: Domain join failing — "The specified domain either does not exist or could not be contacted"
Systematic diagnosis: ping to DC01 by IP succeeded (network OK), but Resolve-DnsName local.lab failed. nslookup revealed the actual DNS server was a UTM IPv6 address (fe80::cc08:faff:fed8:b864) — not DC01. UTM's virtual router was advertising its own IPv6 address as DNS server via DHCPv6, overriding IPv4 settings. Resolution: Disabled IPv6 at the Windows registry level using DisabledComponents = 0xFF, forcing all DNS queries through IPv4 to DC01 (192.168.64.10).
ISSUE: Bridged network mode placed VMs on different subnets (192.168.64.x vs 10.0.0.x)
Switching both VMs to Bridged networking caused Windows 11 to receive a 10.0.0.x DHCP address from the home router while DC01 retained its static 192.168.64.x address. VMs could no longer ping each other. Resolution: Reverted both VMs to UTM Shared Network mode where both operate on the same 192.168.64.x subnet. The IPv6 DNS issue was addressed at the registry level instead.
ISSUE: GPO legal banner values not populating on ARM64 Windows 11 client
GPO registry string values applied correctly server-side (confirmed via Get-GPRegistryValue) but did not propagate to client registry after gpupdate /force. Resolution: Applied registry values directly via Set-ItemProperty as a workaround. Noted as an ARM64 Windows 11 GPO quirk — production x64 systems apply these correctly via GPO without manual intervention.
ISSUE: Password reset rejected — "Does not meet complexity or history requirement"
Attempted to reset rjohnson's password to "NewP@ss456!" which was rejected by the domain password policy configured in Chapter 3. This was not a bug — it was the security control working correctly. Resolution: Used a stronger, unique password (G0v3rnm3nt@Lab2026!) that met all complexity requirements and was not in the 24-password history. Lesson: your own security policies will enforce themselves against you too.
ISSUE: PowerShell multiline paste executing commands in reverse order
Pasting multiline PowerShell commands into the VM caused the terminal to interpret them in reverse — running the last line first, which caused "null object" errors since variables hadn't been assigned yet. Resolution: Converted all multiline scripts to single-line commands using semicolons and backtick-n for newlines, or ran each line individually. This is a known quirk of terminal paste behavior in virtualized environments.
